# صورت مسئله
1. دو سرویس بک‌اند داریم که هر کدام در پاسخ به درخواست اعلام می‌کند شماره یک هست یا دو.
1. یک انجین ایکس به عنوان تنظیم کننده بار روی این دو بک‌اند سوار می‌شود و با الگوریتم RR تنظیم بار می‌کند.
1. یک هدر سفارشی با نام LB-TYPE در پاسخ مشتری افزوده می‌شود که مقدار آن در زمان راه‌اندازی سرویس انجین ایکس از متغیر محیطی خوانده می‌شود.
1. لاگ‌های انجین ایکس به صورت روزانه و تا سه روز ذخیره می‌شود.
1. نحوه اجرا هم با `docker run` و هم با `docker compose` خواهد بود.

# توضیحات فنی

## سرویس Nginx

### فایل پیکربندی 
- افزودن دستور `resolver 127.0.0.11` به بلوک upstream به منظور استفاده از نام کانتینرهای بک‌اند
- افزودن دو خط زیر به بلوک `server` قسمت `/ location` به منظور افزودن یک Header جدید به پاسخ طبق صورت مسئله:
```nginx
    add_header LB-TYPE "${LB_TYPE}" always;
    proxy_set_header LB-TYPE "${LB_TYPE}";
```
همچنین به‌منطور بهینه‌سازی عملکرد loadbalancer در هنگام دردسترس نبودن یک بک‌اند، از گزینه‌های زیر استفاده شده است:
- افزودن `max_fails` و `fail_timeout` به هر upstream
- افزودن `keepalive` برای بهبود کیفیت اتصالات
- افزودن `proxy_next_upstream_tries` و `proxy_next_upstream_timeout` به بلوک `server` قسمت `/ location`

### نصب و پیکربندی logrotate
برای ذخیره روزانه لاگ‌ها و به مدت حداکثر سه روز، از ابزار logrotate استفاده شد که با دستور
```bash
apt update && apt install -y logroate
```
نصب و به‌طور خودکار اجرا می‌گردد و همچنین یک فایل پیکربندی در مسیر `etc/logrotate.d/nginx/` با محتوای زیر قرار داده می‌شود:
```conf
/var/log/nginx/*.log {
    daily
    rotate 3
    ...
}
```
گزینه‌های کم‌اهمیت به دلیل رعایت اختصار آورده نشده‌اند.

### افزودن entrypoint
برای افزودن امکان تغییر هدر `LB-TYPE` از طریق تنظیم متغیر محیطی `LB_TYPE` از یک entrypoint استفاده شد که با استفاده از دستور `envsubst` مقدار متغیر محیطی در فایل مربوطه جایگزین می‌شود:
```bash
envsubst '${LB_TYPE}' < /tmp/backend.conf.template > /etc/nginx/conf.d/default.conf
```

## بک‌اند

### پیاده‌سازی یک بک‌اند ساده
یک کد پایتونی که با کتابخانه `http` و کلاس `BaseHTTPRequestHandler` پیاده‌سازی شده، نقش بک‌اند را ایفا خواهد کرد.
یک API بسیار ساده که متغیر `SERVER_ID` را از متغیرهای محیطی دریافت می‌کند و به‌عنوان خروجی همان را برمی‌گرداند


## اجرا با `docker run`

### ساخت شبکه داکر
به‌منظور استفاده سرویس انجین‌ایکس از سرویس‌های بک‌اند، لازم است یک شبکه مشترک برای کانتینرها تعریف شود و در هنگام اجرا با سوئیچ `network--` به دستور `docker run` داده شود.
```bash
docker network create eitaa-network
```
### اجرا
کافی است از پوشه اصلی اسکریپت [scripts/restart.sh](scripts/restart.sh) را با پارامتر `run` فراخوانی کنیم


## اجرا با `docker compose`

### اجرا
کافی است از پوشه اصلی اسکریپت [scripts/restart.sh](scripts/restart.sh) را با پارامتر `compose` فراخوانی کنیم


### تنظیم متغیر محیطی `LB_TYPE`
کافی است این متغیر را پیش از فراخوانی اسکریپت اجرا تنظیم نمایید. به‌عنوان نمونه:
```bash
LB_TYPE=NEW_NGINX scripts/run.sh compose
```
